01买一台服务器

去 腾讯云 或 阿里云 官网，搜「轻量应用服务器」—— 注意是「轻量应用服务器」而不是「云服务器 ECS/CVM」。轻量的好处是：控制台简单、自带网页终端、 防火墙是图形化点选的，最适合新手。

产品轻量应用服务器控制台最简单，比同配置的 ECS/CVM 便宜三成以上

1 核 1 GB 够不够？

够。因为「构建官网」这一步是在你自己的电脑上完成的，服务器只负责跑现成的代码， 不需要编译。1 核 1 GB 跑 Node 后端 + nginx 完全没压力。 之所以推荐 2 GB，是因为网页构建（vite build）如果在服务器上跑，1 GB 内存容易中途失败 —— 买大一点省心，差价也就几十块。

02域名与备案：你这种情况怎么选

你的情况是：有域名，但没备案。这个组合决定了下面的选择， 因为国内服务器有一条硬规矩：

硬规矩：中国大陆的服务器，用域名访问 80 / 443 端口必须完成 ICP 备案

不备案的话，用域名打开会直接被拦掉。但是—— 用 http://公网IP:8080 这种「IP + 非 80 端口」的方式访问，是不受影响的，完全能用。

两个方案怎么选

方案 A · 中国香港方案 B · 大陆节点
域名直接可用可以要先备案
HTTPS 小锁随时可上备案后才能上
国内访问速度慢一点，日常够用最快
价格略贵便宜
适合谁想马上用域名对外展示内部先用、对外不着急
建议：先按方案 B 跑通，再决定要不要搬

部署脚本和系统本身不依赖域名，两种方案装的东西一模一样。 所以最省心的路线是：先用大陆节点 + IP:8080 把系统跑通、确认没问题， 之后要么走备案，要么把服务器换成中国香港节点 —— 都是重新双击一次部署脚本的事，数据可以整包搬过去。

如果决定去备案

  • 在云厂商控制台找「备案」入口，全程在线提交，不用寄材料
  • 要求：服务器购买时长 ≥ 3 个月；域名在你名下；域名后缀在工信部许可列表内
  • 周期：一般 1~20 个工作日，各省管局速度不同
  • 备案期间服务器照常用，不影响你用 IP 访问

03买完先做两件事

服务器开好之后，先别急着部署，去控制台做这两件事。加起来 3 分钟。

  1. 设置 root 密码

    控制台 → 找到你的实例 → 「更多」→「重置密码」→ 设一个你自己记得住的密码 → 然后关机再开机（不是重启，是关机再开机，否则密码不生效）。

    新买的机器通常需要你先设密码才能用 SSH 登录，这一步不能跳。

  2. 放行两个端口

    控制台 → 实例 → 「防火墙」→「添加规则」，加上这两条：

    协议端口用途要不要加
    TCP8080官网（对外展示）必须加
    TCP8081后台（你自己用）必须加
    TCP22远程登录，一般默认就开着通常已有
    TCP3100后端内部端口千万别加
    为什么 3100 绝对不能放行

    这个系统的「宽带业务」接口目前没有登录鉴权，谁能访问 3100 谁就能直接读写你的客户和合同数据。 我们让后端只监听在本机内部（127.0.0.1），外面必须先经过 nginx 那道带密码的门。 所以：3100 不出现在云防火墙里，就等于外面碰不到它。

顺手记下公网 IP

实例列表里那个「公网 IP」（形如 123.45.67.89）待会儿要填进配置。 这个 IP 会跟着实例走，只要不销毁实例就不会变。

04一键部署

部署工具已经放在项目的 deploy/ 文件夹里。整套流程是： 在你电脑上把项目打包 → 传到服务器 → 服务器自己装好一切。 你只需要双击一个文件。

第一步：填一行配置

打开 deploy 文件夹，双击 deploy.bat。 第一次它会自动生成一个 deploy.config.txt，然后提示你去填。 用记事本打开它，只有这一行是必须改的：

deploy.config.txt 
SERVER_IP=123.45.67.89

把 123.45.67.89 换成你自己的公网 IP，保存。 其他行先全部不用管（端口、口令之类的都有默认值）。

第二步：再双击一次

保存后，再双击一次 deploy.bat。接下来你会看到它在自动干活：

==> 2/6  构建官网（website -> dist）
    * 构建完成

==> 4/6  准备免密登录密钥

      （接下来会装上免密密钥，以后就不用再输了）

关于那个密码

只有第一次会问你要密码（第 3 步设的那个 root 密码）。 脚本会顺手装一把专属密钥，之后每次部署都是双击即完成，不再问密码。

密码输入时屏幕上不会显示任何字符，这是正常的，照打然后回车就行。

05验证清单

照着顺序点一遍，全绿就说明整套系统真的通了。

#打开这个应该看到不对的话
1 http://IP:8080 官网首页，图片文字都正常 看第 8 节 →「两个地址都打不开」
2 http://IP:8080/api/content/home 一大串 JSON 数据（这是关键一步） 说明 nginx 没反代到后端 → 看日志
3 http://IP:8081 先弹账号密码框，输了之后进数据看板 密码错 → 重跑部署脚本看新密码
4 后台改一条内容 → 刷官网 官网跟着变了 按 Ctrl+F5 硬刷新再试
5 在服务器上跑 pm2 list onlystyle-api 是绿色的 online 是红色 errored → 看 pm2 logs
第 4 条是最重要的一条

它验证的是「后台改的东西，前台真的会变」—— 也就是整套内容中台的闭环。这条通过，说明数据库、接口、官网三者都是通的。

官网接口带了 60 秒缓存，所以改完可能要等一会儿或者硬刷新才看得到，这是正常设计，不是 bug。

06日常运维：记住这几条命令就够

这些命令要在服务器上执行。怎么进服务器？ 云控制台 → 实例 → 「登录」，会打开一个网页版终端，直接就能敲命令。

最常用的五条

服务器终端 
pm2 list                                  # 看服务活着没（online 就对了）
pm2 logs onlystyle-api --lines 50         # 看最近 50 行日志（排查问题必用）
pm2 restart onlystyle-api                 # 重启后端
onlystyle-backup                          # 手动备份一次数据
systemctl restart nginx                   # 重启 nginx（改了网站配置后用）

更新网站内容 / 改代码之后

不需要登录服务器。在本机重新双击一次 deploy.bat 就行 —— 脚本是「幂等」的，可以反复执行，会覆盖掉旧代码，但不会动你的数据（见下一节）。

改后台密码

在本机的 deploy.config.txt 里写上：

deploy.config.txt 
ADMIN_PASS=你的新密码

保存后重新双击 deploy.bat，密码就换好了。

改访问端口

改配置里的 WEB_PORT / ADMIN_PORT，重新部署。 但别忘了去云控制台防火墙放行新端口，否则改了也进不去。

07数据安全（这一节请认真看）

好消息：这个系统的数据就是一个文件

它用的是 SQLite（准确说是 sql.js），没有单独的数据库服务器。 你所有的客户、合同、内容，都在一个大约 240 KB 的文件里： 

/opt/onlystyle/app/biz-os/backend/broadband_os.db

「备份数据」= 复制这个文件。就这么简单。上传的图片素材在同一层目录的 uploads/ 里。

已经帮你配好自动备份

  • 每天凌晨 3:00 自动打包一次数据库 + 上传素材
  • 存放在 /opt/onlystyle/backups/，只保留最近 14 份（更早的自动删）
  • 想立刻备份：在服务器上敲 onlystyle-backup

建议你额外做一件事

服务器如果整台挂了（或者误删实例），本地那份也一起没了。所以每个月下载一份到你自己电脑：

在你自己的电脑上执行 
> scp root@123.45.67.89:/opt/onlystyle/backups/*.tar.gz D:\备份\

（Windows 自带 scp，直接在自己的终端里敲就行，会问一次服务器密码。）

两个绝对不能做的事

① 不要删除 /opt/onlystyle/ 这个目录。 全站的数据、上传的图片、程序本体都在里面，删了等于整站归零（只能靠备份恢复）。

② 不要用你电脑上的数据库去覆盖线上。 你本机的数据库是开发时的旧快照，覆盖上去会把线上真实数据全部冲掉。 部署脚本已经帮你设了保护：如果服务器上已经有数据库，它绝不会覆盖， 而是把你传上去的那份改名成 broadband_os.db.incoming 放着不动。 看到这个文件说明保护生效了，确认不需要就可以删掉。

08故障速查

按「症状」找，基本都在里面。

症状最可能的原因怎么修
两个地址都打不开
最常见		 云控制台防火墙没放行端口（十次里有九次是这个） 控制台 → 防火墙 → 加规则放行 8080 和 8081
浏览器一直转圈，最后超时 端口放行了，但服务没起来 pm2 list 看看是不是 errored，再 pm2 logs onlystyle-api --lines 50
官网能打开，但页面是白屏 官网构建产物没传上去 本机重新双击 deploy.bat（注意看第 2 步构建有没有报错）
官网能打开，但 /api/... 返回 502 nginx 正常，后端挂了 pm2 restart onlystyle-api，还不行就看日志
官网能打开，但页面没有内容 接口没反代成功 先单独访问 http://IP:8080/api/content/home，确认能出 JSON
后台能改，官网死活不变 浏览器缓存了旧内容（接口有 60 秒缓存） 按 Ctrl+F5 硬刷新；等 1 分钟再试
后台的图片传上去不显示 uploads 目录权限问题 服务器上执行 chmod -R a+rX /opt/onlystyle/app
提示 Permission denied (publickey,password) root 密码没设，或 22 端口没放行 回第 3 节：重置密码 + 关机再开机 + 放行 22
提示 取不到 Node 下载地址 服务器连不上外网 检查云防火墙的「出网」规则，或先用 curl -I https://www.baidu.com 测一下
打开是 nginx 的欢迎页 系统自带的默认站点抢了请求 服务器上执行 rm -f /etc/nginx/sites-enabled/default && systemctl restart nginx
上传大文件（比如视频）失败 nginx 请求体大小限制 脚本已设成 20 MB；更大的话改 client_max_body_size 后重启 nginx
合同状态在早上不对劲 服务器时区不是东八区 脚本已自动设成 Asia/Shanghai；用 date 确认一下
还是搞不定？

把这三样发我，基本能定位： ① 服务器上 pm2 logs onlystyle-api --lines 80 的输出； ② nginx -t 的输出； ③ 你双击部署时那个黑窗口里的完整文字。

09后续可选（不着急）

先跑通，这些等有需要的时候再做。

上一个 HTTPS 小锁

前提是域名已经能访问（即：中国香港节点，或大陆节点已备案完成）。然后：

deploy.config.txt 
DOMAIN=example.com
USE_HTTPS=1

重新双击 deploy.bat。脚本会额外生成 example.com、www.example.com（官网） 和 admin.example.com（后台）三个站点，并自动申请一个免费的 Let's Encrypt 证书，自动续期，永久免费。

用之前先确认：域名的 DNS 解析里，这三条记录都指向了服务器公网 IP。

其他可以慢慢加的

想做说明
给宽带业务接口加真正的登录鉴权目前用 nginx 的密码框兜着，属于「先锁上门」；正式的多角色权限是下一阶段的事
官网做搜索引擎优化（预渲染）项目里预留了 scripts/prerender.js，还没实现
字体自托管目前回落到系统字体，装上品牌字体会更统一
把上传素材搬去对象存储图片视频多了以后，能省服务器带宽
加监控告警服务挂了自动发消息给你
一个已经知道的小毛病

后端的自动状态更新（每天 9:00 那次）用了一个会在特定情况下差一天的取日期写法， 理论上在东八区凌晨 0:00~8:00 之间可能让合同状态判断错一天。 脚本已经把服务器时区设对了，所以只在很窄的时间窗口有点影响。 这是个独立的代码修复，需要你确认后我再动源码——目前没有改动任何业务代码。

B那个脚本到底做了什么

整个过程分成两半：你电脑上的 deploy.cjs，和服务器上的 bootstrap.sh。 它一共做这些事，都是自动的：

在你电脑上（约 1 分钟）

  1. 读取 deploy.config.txt
  2. 构建官网（vite build → website/dist）
  3. 打包「后端 + 后台界面 + 官网产物 + 数据库」，排除掉 node_modules、开发素材和历史备份快照（24 MB → 压缩后 23 MB）
  4. 生成一把仅用于部署的 SSH 密钥，装到服务器上实现免密登录
  5. 把安装包和脚本上传到服务器的 /tmp/

在服务器上（约 2~5 分钟）

  1. 识别系统

    自动判断是 apt 还是 yum/dnf，Ubuntu、Debian、CentOS 都能跑

  2. 把时区设成 Asia/Shanghai

    不能省。后端有「每天 9:00 自动检查合同到期」的定时任务，时区错了状态就会差一天。

  3. 装基础软件

    nginx、curl、tar、xz、openssl、证书包

  4. 装 Node.js 22

    走国内镜像 registry.npmmirror.com，比官方源快很多。已经装过就跳过。

  5. 解包代码

    放到 /opt/onlystyle/app。 如果服务器上已经有数据库，会先备份一份，然后保留线上那份， 把你上传的改名为 .incoming，绝不覆盖。

  6. 装后端依赖 + 配进程守护

    用 pm2 托管后端，崩溃自动重启、开机自动启动。 同时把后端改成只监听 127.0.0.1，外面碰不到 3100。

  7. 写 nginx 配置

    8080 给官网（静态文件 + 把 /api、/uploads 转给后端）， 8081 给后台（全量转给后端，并加一道账号密码），配了域名就再加三个域名站点。

  8. 装备份

    写一个 onlystyle-backup 命令，并注册每天 3:00 的定时任务，保留最近 14 份。

  9. 放行本机防火墙

    如果服务器自己开了 ufw/firewalld，会自动放行 22、8080、8081。

  10. 可选：申请 HTTPS 证书

    只有配置里填了域名并开了 USE_HTTPS 才会做。

它是幂等的

「幂等」= 跑一百次和跑一次的结果一样。随时可以重新双击部署，把服务器刷成最新状态。 已经装好的不会重复装、不会报错，唯一会「覆盖」的是代码，而数据永远受保护。

C常见疑问

必须买云服务器吗？能不能用宝塔面板那种图形化的？

可以用宝塔，但没必要。宝塔省下的是「装环境」的功夫，而我们的脚本已经把这步自动化了； 用宝塔反而要多点十几下鼠标，而且宝塔本身是个额外的安全面。脚本这条路更快也更干净。

能不能不用服务器，用 Vercel / Zeabur 这类托管平台？

技术上可以，但不推荐。这套系统用的是「单文件 SQLite + 本地 uploads 目录」， 托管平台讲究无状态，必须额外买持久化卷才能保住数据，配置反而更麻烦、还可能丢数据。 而且国内访问这些平台的速度通常不理想。

用一个域名同时放官网和后台行吗？

行，但建议用子域名分开，比如官网 www.example.com、后台 admin.example.com。 脚本就是这个方案。好处是后台那道密码门可以单独加，不会影响官网访客。

我本机上的演示数据（30 个客户 / 46 份合同）会一起传上去吗？

首次部署会传上去（这样你一打开就有东西看，不是空壳）。 之后每次重新部署都不会再覆盖线上的数据。 想把演示数据清掉：node design/mockups/dashboard-redesign/seed-demo-data.cjs --reset， 但这个命令要停掉本地后端才能跑，而且只影响本机，线上要清得单独处理 —— 需要的话告诉我。

我电脑上要装什么吗？

只要能跑 Node.js（脚本会自己找）和系统自带的 ssh/scp/tar。 Windows 10 及以上这些都自带，不用额外装任何东西。

部署失败了怎么办？会不会把服务器搞坏？

不会。脚本每一步都会检查，出错就停下并告诉你卡在哪一步。 它是幂等的，修好问题重新双击就行，不会因为「跑到一半」而留下坏掉的状态。 而且它从不删除任何数据 —— 唯一会覆盖的是程序代码。

一年之后要续费多少？

看机型。新用户首年的低价通常不延续，续费价大约 ¥300/年左右（2核2G）。 有几个办法：关注「同价续费」的机型、买 3 年/5 年的长期套餐（常低至 2 折）、或者到期前迁移到新活动机型 —— 因为这套部署是一键的，换服务器成本很低（数据整包搬走即可）。

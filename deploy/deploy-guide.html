01买服务器（两台）

去 腾讯云 或 阿里云 官网，搜「轻量应用服务器」—— 注意是「轻量应用服务器」而不是「云服务器 ECS/CVM」。轻量的好处是：控制台简单、自带网页终端、 防火墙是图形化点选的，最适合新手。

1 核 1 GB 够不够？

够。因为「构建官网」这一步是在你自己的电脑上完成的，服务器只负责跑现成的代码， 不需要编译。1 核 1 GB 跑 Node 后端 + nginx 完全没压力。 之所以推荐 2 GB，是因为网页构建（vite build）如果在服务器上跑，1 GB 内存容易中途失败 —— 买大一点省心，差价也就几十块。

02域名与备案：你这种情况怎么选

你的情况是：有域名，但没备案。这个组合决定了下面的选择， 因为国内服务器有一条硬规矩：

硬规矩：中国大陆的服务器，用域名访问 80 / 443 端口必须完成 ICP 备案

不备案的话，用域名打开会直接被拦掉。但是—— 用 http://公网IP:8085 直连官网（后端 3100 同理）做自测是不受影响的、完全能用。 注意现网架构下这两个端口刻意不对公网开放，所以自测时要么临时对某个 IP 放行、 要么直接在服务器上 curl；对外正式访问仍然必须走域名 + 备案。

两个方案怎么选

方案 A · 中国香港方案 B · 大陆节点
域名直接可用可以要先备案
HTTPS 小锁随时可上备案后才能上
国内访问速度慢一点，日常够用最快
价格略贵便宜
适合谁想马上用域名对外展示内部先用、对外不着急
建议：先按方案 B 跑通，再决定要不要搬

部署脚本和系统本身不依赖域名，两种方案装的东西一模一样。 所以最省心的路线是：先用大陆节点 + IP:8085 把系统跑通、确认没问题， 之后要么走备案，要么把服务器换成中国香港节点 —— 都是重新双击一次部署脚本的事，数据可以整包搬过去。

如果决定去备案

  • 在云厂商控制台找「备案」入口，全程在线提交，不用寄材料
  • 要求：服务器购买时长 ≥ 3 个月；域名在你名下；域名后缀在工信部许可列表内
  • 周期：一般 1~20 个工作日，各省管局速度不同
  • 备案期间服务器照常用，不影响你用 IP 访问

03买完先做两件事

服务器开好之后，先别急着部署，去控制台做这两件事。加起来 3 分钟。

  1. 设置 root 密码

    控制台 → 找到你的实例 → 「更多」→「重置密码」→ 设一个你自己记得住的密码 → 然后关机再开机（不是重启，是关机再开机，否则密码不生效）。

    新买的机器通常需要你先设密码才能用 SSH 登录，这一步不能跳。

  2. 放行端口（注意：现网是两台机器）

    控制台 → 实例 → 「防火墙」→「添加规则」。两台机器的规则不一样，别搞混：

    机器端口用途怎么放
    应用服务器22远程登录（部署脚本要用）通常已有
    应用服务器3100后端 API（接口 + 后台）只给代理机 IP
    应用服务器8085官网静态站只给代理机 IP
    代理服务器80 / 443公网入口（Nginx）对公网开放
    3100 / 8085 绝对不能对公网放行

    这套系统的「宽带业务」接口目前没有登录鉴权，谁能访问 3100 谁就能直接读写你的客户和合同数据。 所以这两个端口只允许代理服务器访问：最好把两台机器放进同一个内网/VPC， 代理机用内网 IP 回源 —— 这样公网连这两个端口的影子都看不到。

    公网入口只有代理服务器上的 80 / 443。外人能碰到的永远只有 Nginx。

顺手记下公网 IP

实例列表里那个「公网 IP」（形如 123.45.67.89）待会儿要填进配置。 这个 IP 会跟着实例走，只要不销毁实例就不会变。

04一键部署

部署工具已经放在项目的 deploy/ 文件夹里。整套流程是： 在你电脑上把项目打包 → 传到服务器 → 服务器自己装好一切。 你只需要双击一个文件。

第一步：填一行配置

打开 deploy 文件夹，双击 deploy.bat。 第一次它会自动生成一个 deploy.config.txt，然后提示你去填。 用记事本打开它，只有这一行是必须改的：

deploy.config.txt 
SERVER_IP=123.45.67.89

把 123.45.67.89 换成你自己的公网 IP，保存。 其他行先全部不用管（端口、口令之类的都有默认值）。

第二步：再双击一次

保存后，再双击一次 deploy.bat。接下来你会看到它在自动干活：

只有第一次会问你要密码（第 3 步设的那个 root 密码）。 脚本会顺手装一把专属密钥，之后每次部署都是双击即完成，不再问密码。

05验证清单

照着顺序点一遍，全绿就说明整套系统真的通了。

#打开这个应该看到不对的话
1 服务器上 curl -I http://127.0.0.1:3100/ 返回 200（后端活着） 不通 → pm2 logs onlystyle-api
2 服务器上 curl -I http://127.0.0.1:8085/ 返回 200（官网静态站活着） 不通 → pm2 logs onlystyle-web
3 代理机上 curl -I http://127.0.0.1/ 返回 200（代理转发通了） 502 / 521 → upstream 的 __APP_HOST__ 没替换或指错
4 https://www.onlystyle.com.cn 官网首页，图片文字都正常 壳出来但没内容 → 代理机 www 配置漏了 /api/ 那两条
5 https://bos.onlystyle.com.cn 后台登录页 → 用员工账号登录进数据看板 账号错 → 管理员在「人员管理」里重置
6 后台改一条内容 → 刷官网 官网跟着变了 按 Ctrl+F5 硬刷新再试
7 服务器上跑 pm2 list onlystyle-api 与 onlystyle-web 都是绿色 online 红色 errored → 看 pm2 logs
第 6 条是最重要的一条

它验证的是「后台改的东西，前台真的会变」—— 也就是整套内容中台的闭环。这条通过，说明数据库、接口、官网三者都是通的。

官网接口带了 60 秒缓存，所以改完可能要等一会儿或者硬刷新才看得到，这是正常设计，不是 bug。

06日常运维：记住这几条命令就够

这些命令要在服务器上执行。怎么进服务器？ 云控制台 → 实例 → 「登录」，会打开一个网页版终端，直接就能敲命令。

最常用的五条

服务器终端 
pm2 list                                  # 看两个进程活着没（online 就对了）
pm2 logs onlystyle-api --lines 50         # 后端日志（排查接口问题必用）
pm2 logs onlystyle-web --lines 50         # 官网日志
pm2 restart onlystyle-api                 # 重启后端
pm2 restart onlystyle-web                 # 重启官网
onlystyle-backup                          # 手动备份一次数据

更新网站内容 / 改代码之后

不需要登录服务器。在本机重新双击一次 deploy.bat 就行 —— 脚本是「幂等」的，可以反复执行，会覆盖掉旧代码，但不会动你的数据（见下一节）。

改后台账号密码

后台已经没有「配置文件里的密码」了 —— 直接在管理台里改： 用管理员账号登录 →「系统管理 → 人员管理」→ 选人 → 改密码 / 改角色。

管理员自己进不去时，让另一位管理员帮你重置。

改端口 / 域名

官网固定 8085、后端固定 3100，由项目根目录的 ecosystem.config.js 决定（这是唯一真相源，部署时会随包发到服务器）。 真要改端口，必须两处一起改，否则代理就指错了：

  1. 应用服务器上 ecosystem.config.js 里的端口
  2. 代理服务器上 /etc/nginx/conf.d/00-onlystyle-upstream.conf 里的 upstream 端口

改完在应用服务器 pm2 restart all，再到代理机 nginx -t && systemctl reload nginx。

07数据安全（这一节请认真看）

好消息：这个系统的数据就是一个文件

它用的是 SQLite（准确说是 sql.js），没有单独的数据库服务器。 你所有的客户、合同、内容，都在一个大约 240 KB 的文件里： 

/opt/business-os/biz-os/backend/broadband_os.db

「备份数据」= 复制这个文件。就这么简单。上传的图片素材在同一层目录的 uploads/ 里。

已经帮你配好自动备份

  • 每天凌晨 3:00 自动打包一次数据库 + 上传素材
  • 存放在 /opt/business-os/backups/，只保留最近 14 份（更早的自动删）
  • 想立刻备份：在服务器上敲 onlystyle-backup

建议你额外做一件事

服务器如果整台挂了（或者误删实例），本地那份也一起没了。所以每个月下载一份到你自己电脑：

在你自己的电脑上执行 
> scp root@123.45.67.89:/opt/business-os/backups/*.tar.gz D:\备份\

（Windows 自带 scp，直接在自己的终端里敲就行，会问一次服务器密码。）

两个绝对不能做的事

① 不要删除 /opt/business-os/ 这个目录。 全站的数据、上传的图片、程序本体都在里面，删了等于整站归零（只能靠备份恢复）。

② 不要用你电脑上的数据库去覆盖线上。 你本机的数据库里往往只有测试客户，覆盖上去会把线上真实数据全部冲掉。 部署脚本已经帮你设了保护：如果服务器上已经有数据库，它绝不会覆盖， 而是把你传上去的那份改名成 broadband_os.db.incoming 放着不动。 看到这个文件说明保护生效了，确认不需要就可以删掉。

③ 同步内容请用 scripts/content-sync.cjs，不要整库覆盖。 数据库里同时躺着「内容」（官网/后台的文案、导航、logo、案例）和 「业务」（客户、合同、线路、员工）。整库覆盖 = 业务数据一起没。 正确做法是只换内容域：node scripts/content-sync.cjs --from 你那份最新的.db

08故障速查

按「症状」找，基本都在里面。

症状最可能的原因怎么修
域名打不开 / 502
最常见		 代理机 upstream 的 __APP_HOST__ 没替换，或指错了地址 改 deploy/nginx/onlystyle-upstream.conf → nginx -t && systemctl reload nginx
域名全部超时 代理机 80/443 没放行，或 DNS 没解析到代理机 控制台放行 80/443；dig www.onlystyle.com.cn 确认指向代理机
官网能开，但内容全空 代理机 www 配置漏了 /api/、/uploads/ 两条 location 补齐后 reload（见 deploy/nginx/README.md）
官网能打开，但页面是白屏 官网构建产物没传上去 本机重新双击 deploy.bat（注意看构建有没有报错）
域名能开，但 /api/... 返回 502 Nginx 正常，后端挂了 pm2 restart onlystyle-api，还不行就看日志
后台打不开 3100 没被代理机连上 代理机上 curl -I http://<APP_HOST>:3100/ 自测；查安全组是否允许代理机访问 3100
后台能改，官网死活不变 浏览器缓存了旧内容（接口有 60 秒缓存） 按 Ctrl+F5 硬刷新；等 1 分钟再试
后台的图片传上去不显示 uploads 目录权限问题 服务器上执行 chmod -R a+rX /opt/business-os
提示 Permission denied (publickey,password) root 密码没设，或 22 端口没放行 回第 3 节：重置密码 + 关机再开机 + 放行 22
提示 取不到 Node 下载地址 服务器连不上外网 检查云防火墙的「出网」规则，或先用 curl -I https://www.baidu.com 测一下
打开是 nginx 的欢迎页 代理机上有系统自带的 default 站点抢了请求 代理机上执行 rm -f /etc/nginx/sites-enabled/default && systemctl reload nginx
上传证书 / 大图失败（413） 代理机 client_max_body_size 太小 脚本模板已设成 25m；改过就恢复，然后 reload nginx
合同状态在早上不对劲 服务器时区不是东八区 脚本已自动设成 Asia/Shanghai；用 date 确认一下
还是搞不定？

把这三样发我，基本能定位： ① 应用服务器上 pm2 logs onlystyle-api --lines 80 的输出； ② 代理机上 nginx -t 的输出； ③ 你双击部署时那个黑窗口里的完整文字。

09后续可选（不着急）

先跑通，这些等有需要的时候再做。

上一个 HTTPS 小锁

前提是域名已解析到代理服务器（中国香港节点，或大陆节点已备案完成）。然后在代理机上执行：

代理服务器 
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d www.onlystyle.com.cn -d onlystyle.com.cn -d bos.onlystyle.com.cn --redirect

certbot 会自动改好 Nginx 配置并处理续期，证书免费、自动续，永久有效。 注意证书装在代理机上 —— 应用服务器只跑 3100/8085、不接触公网，也不需要证书。

上完 HTTPS 后，微信公众平台的回调地址要改成 https://bos.onlystyle.com.cn/api/wechat/callback， 并把后台「系统设置 → 微信配置」里的回调地址同步成 https://bos.onlystyle.com.cn/wechat/callback。

其他可以慢慢加的

想做说明
给宽带业务接口加真正的登录鉴权后端业务接口目前是零鉴权，只靠「3100 / 8085 不暴露到公网」兜着；正式的接口鉴权是下一阶段的事

加监控告警服务挂了自动发消息给你
一个已经知道的小毛病

后端的自动状态更新（每天 9:00 那次）用了一个会在特定情况下差一天的取日期写法， 理论上在东八区凌晨 0:00~8:00 之间可能让合同状态判断错一天。 脚本已经把服务器时区设对了，所以只在很窄的时间窗口有点影响。 这是个独立的代码修复，需要你确认后我再动源码——目前没有改动任何业务代码。

B那个脚本到底做了什么

整个过程分成两半：你电脑上的 deploy.cjs，和服务器上的 bootstrap.sh。 它一共做这些事，都是自动的：

在你电脑上（约 1 分钟）

  1. 读取 deploy.config.txt
  2. 构建官网（vite build → website/dist）
  3. 打包「后端 + 后台界面 + 官网产物 + pm2 定义 + 数据库」，排除掉 node_modules、开发素材和历史备份快照（24 MB → 压缩后 23 MB）
  4. 生成一把仅用于部署的 SSH 密钥，装到服务器上实现免密登录
  5. 把安装包和脚本上传到服务器的 /tmp/

在服务器上（约 2~5 分钟）

  1. 识别系统

    自动判断是 apt 还是 yum/dnf，Ubuntu、Debian、CentOS 都能跑

  2. 把时区设成 Asia/Shanghai

    不能省。后端有「每天 9:00 自动检查合同到期」的定时任务，时区错了状态就会差一天。

  3. 装基础软件

    curl、tar、xz、openssl、证书包（刻意不装 nginx，公网入口在代理机）

  4. 装 Node.js 22

    走国内镜像 registry.npmmirror.com，比官方源快很多。已经装过就跳过。

  5. 解包代码

    放到 /opt/business-os。 如果服务器上已经有数据库，会先备份一份，然后保留线上那份， 把你上传的改名为 .incoming，绝不覆盖。

  6. 装后端依赖 + 配进程守护

    用包内 ecosystem.config.js 起两个 pm2 进程 （onlystyle-api:3100 + onlystyle-web:8085）， 崩溃自动重启、开机自动启动。

    ⚠️ 旧版会「把后端改成只监听 127.0.0.1」—— 那段已彻底删除： 代理机是另一台机器，只听本机地址会直接连不通。安全边界靠安全组，不靠绑地址。

  7. 提示代理机配置位置

    脚本不在应用服务器上装 nginx，而是提示你去代理机安装 deploy/nginx/ 里的 upstream + 两个域名 server 块。

  8. 装备份

    写一个 onlystyle-backup 命令，并注册每天 3:00 的定时任务，保留最近 14 份。

  9. 放行本机防火墙

    只放行 22；3100 / 8085 保持关闭，并提示你去云安全组收紧为「仅代理机可访问」。

  10. HTTPS 证书

    证书在代理服务器上用 certbot 申请（脚本不处理），见第 9 节。

它是幂等的

「幂等」= 跑一百次和跑一次的结果一样。随时可以重新双击部署，把服务器刷成最新状态。 已经装好的不会重复装、不会报错，唯一会「覆盖」的是代码，而数据永远受保护。

C常见疑问

必须买云服务器吗？能不能用宝塔面板那种图形化的？

可以用宝塔，但没必要。宝塔省下的是「装环境」的功夫，而我们的脚本已经把这步自动化了； 用宝塔反而要多点十几下鼠标，而且宝塔本身是个额外的安全面。脚本这条路更快也更干净。

能不能不用服务器，用 Vercel / Zeabur 这类托管平台？

技术上可以，但不推荐。这套系统用的是「单文件 SQLite + 本地 uploads 目录」， 托管平台讲究无状态，必须额外买持久化卷才能保住数据，配置反而更麻烦、还可能丢数据。 而且国内访问这些平台的速度通常不理想。

用一个域名同时放官网和后台行吗？

行，但现网用的是两个子域名分开：官网 www.onlystyle.com.cn、 后台 bos.onlystyle.com.cn。好处是两个入口能各自配证书、各自做缓存策略，互不影响。

我本机数据库里的东西会一起传上去吗？

首次部署（服务器上还没有数据库时）会采用安装包里的那份 —— 相当于用你的数据初始化。 此后每次重新部署都不会再覆盖线上的数据库，你传上去的那份会被改名成 broadband_os.db.incoming 放着不动。

要同步内容（官网/后台的文案、导航、logo、案例）而不动业务数据， 用 node scripts/content-sync.cjs --from 你的.db —— 它只换内容域， 客户 / 合同 / 线路 / 员工原样保留。

我电脑上要装什么吗？

只要能跑 Node.js（脚本会自己找）和系统自带的 ssh/scp/tar。 Windows 10 及以上这些都自带，不用额外装任何东西。

部署失败了怎么办？会不会把服务器搞坏？

不会。脚本每一步都会检查，出错就停下并告诉你卡在哪一步。 它是幂等的，修好问题重新双击就行，不会因为「跑到一半」而留下坏掉的状态。 而且它从不删除任何数据 —— 唯一会覆盖的是程序代码。

一年之后要续费多少？

看机型。新用户首年的低价通常不延续，续费价大约 ¥300/年左右（2核2G）。 有几个办法：关注「同价续费」的机型、买 3 年/5 年的长期套餐（常低至 2 折）、或者到期前迁移到新活动机型 —— 因为这套部署是一键的，换服务器成本很低（数据整包搬走即可）。
